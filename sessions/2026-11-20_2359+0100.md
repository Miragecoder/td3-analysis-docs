# Waypoint state (opponent start index) and “Generate AI paths” improvement

## Context / question
- Reviewed `AI_AGENT.md` and scanned referenced dirs (`Game/`, `td3-analysis-docs/docs|sessions|repos/...`).
- User question: in the Course Editor’s **“Generate SCENE03”** (Pacific inversion) flow, opponent entities often start with **Waypoint State `0x0043`**, causing a U-turn at race start; fixing manually means setting to **`0x0041`** and re-generating route branch scripts. Asked: *“What is up with this 'waypoint state' anyways?”*

## Findings (from code/docs)
- **Waypoint State** is the map entity waypoint word (`MAP_ENTITY_LAYOUT.waypoint` in `map-inspection.ts`); UI hint: **low 6 bits = lane waypoint index**. It’s part of the AI/traffic lane-following state together with cell, position, behavior, and opponent branch scripts (`DS_opp_scripts` at map `+0x05`, two 10-byte blocks for opponent models 0x02/0x03).
- Lane connectivity is defined by tile lane banks (`SCENETTP.BIN` / scene `P.BIN`) + cell rotation; wrong start index can pick the wrong exit and lead to immediate U-turn/backtrack/fallback behavior. Docs: `docs/map-entities-and-gameplay.md`, `docs/course-lane-connectivity.md`, `docs/course-inversion-feasibility.md`.
- In **`invertPacificCourse`** (`td3-analysis-docs/repos/testdrive3-course-editor/src/shared/course-inversion.ts`), opponent waypoint can be forced in special cases (e.g. `inverseIntersectionFinish` sets `opponentWaypoint = 0x43`; special leg-3/start-tile cases may use `0x40` because index 3 is invalid). The chosen default can be wrong for the transformed start tile/orientation, producing the observed start U-turn.
- `writeOpponentRouteScript` syncs the entity behavior nibble with the script initial mode, so waypoint index and branch scripts must stay consistent after changes.

## Change request
- “Can we make the **‘Generate AI paths’** feature include picking the right initial Waypoint State? … the editor can see possible choices and the right one leads to a shorter path.”

## Implementation (course editor source)
Modified in `td3-analysis-docs/repos/testdrive3-course-editor`:

- `src/shared/route-probe.ts`
  - `probeOpponentPaths` now accepts optional `startWaypointIndex` (overrides `entity.waypoint & 0x3F` for the probe start). Logging updated to show the effective start waypoint index.

- `src/browser/editor.ts` (`probeAiPaths`)
  - For each opponent, derives start cell/tile from the current entity and the loaded lane bank; builds candidate start waypoint indices = `{current low6} ∪ {all lane waypoint indices for that start tile}` (when lane known).
  - Probes each candidate; selects the candidate whose best finish-reaching result is best (prefers any that reaches finish; among those prefers fewer steps, then fewer script control points, then fewer branch modes), matching existing ranking style.
  - After selecting the best path pair/scripts (existing pairing logic), writes each opponent’s **Waypoint State**: `newWp = (entity.waypoint & ~0x3F) | (chosenIndex & 0x3F)` via `writeMapEntity`, then writes route scripts via `writeOpponentRouteScript`.
  - Console logs include the chosen start waypoint index.

## Notes
- Source changes only in this workspace; rebuilding the editor (`npm run build` in the course-editor repo) is required for `dist/` if used, but `node`/`npm` were not available in the sandbox to typecheck/build here.
- Rationale: automates the manual workaround (pick correct start index, then regenerate/apply scripts) by searching start indices against lane data + path probing.
