# AI branch scripts: semantics, SCENE03 Leg 1 tracing/fix, and course-editor updates

Investigated Test Drive III opponent (AI) branch scripts and applied findings to
`Game/SCENE03.DAT` (Leg 1) and the course editor.

## Branch script semantics (code/docs review)

- Opponent scripts are stored per map at header offset `+0x05` as two 10-byte
  blocks (`DS_opp_scripts`, one per opponent/model 2 and 3). Byte 0 is the
  initial mode/behavior; bytes 1.. are consumed in order at script-control
  waypoints (`wf & 0xBF3F` in `vehicle_follow_lane`).
- `sim_traffic.c` (`testdrive3-enhanced-analysis`) behavior/branch mapping:
  `2 -> branch mode 0`, `3 -> mode 1 (low 6-bit waypoint offset if present)`,
  `4 -> mode 2 (high 6-bit waypoint offset if present)`; `0` terminates the
  opponent run. Modes `5/6/7` randomize among branch choices.
- **Timing nuance:** branch mode for the current waypoint step is derived from
  the object’s current behavior (`(flags >> 8) & 0x0F`) before script
  consumption; on control-point consumption the engine pre-increments
  `script_pos` and stores `opp_scripts[k][pos]` (indices 1..) as future
  behavior, without recomputing the branch for that same step.
- Interpretation: `2` is effectively the default/straight-through choice (next
  waypoint, offset `+1` in the normal case), while `3/4` select alternate
  branch offsets/strategies encoded in waypoint flags. `3`/`4` are not
  universally hardcoded geometric right/left turns; the actual direction depends
  on lane waypoint data/tile geometry (a useful heuristic in many cases, but
  not guaranteed).

## SCENE03 Leg 1 verification and tracing (`Game/SCENE03.DAT`)

- Inspected fresh `Game/SCENE03.DAT` / `SCENE03.LST` (Leg 1, map offset 66112,
  `LST` byte 87 = 0 => shared `SCENETTP.BIN` from `DATAB.DAT`). Opponents start
  at cell `(4,13)`, waypoint idx `1`.
- Fresh scripts read from header:
  - Opponent 1 (slot 1/model 2): `[2,2,2,2,0,...]` (initial 2, consumed steps
    `[2,2,2]`, terminates)
  - Opponent 2 (slot 2/model 3): `[4,4,2,0,...]` (initial 4, consumed steps
    `[4,2]`, terminates)
- Traced script-control points (engine-equivalent lane traversal, shared bank):
  - Opp 1: `(6,13)` tile `0x24` rot 3 wp2 `0x0400` (script[1]=2), `(11,14)`
    tile `0x15` wp7 `0x003D` (script[2]=2), `(28,11)` tile `0x16` wp15 `0x430A`
    (script[3]=2), `(29,11)` tile `0x59` wp1 `0x0101` terminator.
  - Opp 2: `(6,13)` tile `0x24` rot 3 wp2 `0x0400` (script[1]=4, branch via
    behavior 4 => offset +4/left), `(28,11)` tile `0x16` wp8 `0x433C`
    (script[2]=2), `(29,11)` tile `0x59` wp1 `0x0101` terminator.

## In-game issue diagnosis and fix (Opponent 2, Leg 1)

- Reported symptom: Opponent 2 went straight at `(6,13)` instead of taking the
  intended left turn (traffic could take the turn). Lane data at `(6,13)` tile
  `0x24` rot 3 wp2 (`flags 0x0400`, high offset 4) gives `+1` (straight/east to
  `(7,13)`) for behavior/mode 0-1 and `+4` (left/north to `(6,12)`) for
  behavior/mode 2.
- Cause: entity behavior mismatch — slot 2 flags were `0x63C3` (behavior nibble
  3) while script/header initial byte was 4, so the branch at wp2 used behavior
  3 before consuming script[1]=4.
- **Patched `Game/SCENE03.DAT`:** Leg 1, slot 2 entity flags at offset `69931`
  changed `0x63C3 -> 0x64C3` (behavior nibble 3 -> 4). In-game retest confirmed
  Opponent 2 took the intended route.

## Opponent 1 `(28,11)` observation and temporary instrumentation

- Observed one run where Opponent 1 turned right at `(28,11)` instead of
  straight. Static data/trace for wp15 (`flags 0x430A`, tile `0x16` rot 2)
  predicts straight with behavior 2 (`+1` to `(29,11)`); a right turn matches
  behavior 3 (`+10`, south branch).
- Added temporary `[AI-OPP1]` debug logging in
  `td3-analysis-docs/repos/testdrive3-enhanced-analysis/src/game/sim_traffic.c`
  (step/script/branch/exit/target around the area). In the rebuilt logged run
  the route was correct (`beh=2`, `bm=0`, offset `+1` at wp15), so the issue was
  not reproduced there; logging was reverted. This suggests static script/lane
  tracing is necessary but not always sufficient, and runtime state/conditions
  may affect outcomes in some cases.

## Course editor changes (`repos/testdrive3-course-editor`)

- `src/shared/map-inspection.ts`: `writeOpponentRouteScript(...)` now syncs the
  opponent entity’s behavior nibble with `initialMode` when writing scripts
  (`(flags & 0xF0FF) | ((initialMode & 0x0F) << 8)` for model 2/3), preventing
  script/entity initial-behavior mismatches.
- `src/browser/editor.ts`: **Generate AI paths** simplified to a single
  generate-and-apply action (probes, selects best path(s), applies immediately,
  and reports the applied result) with no intermediate suggestion/apply-step UI.

## Notes

- Enhanced-analysis debug logging was reverted; no lasting source changes there.
- `Game/SCENE03.DAT` retains the Leg 1 Opponent 2 entity-behavior patch
  (`0x64C3`) applied for testing. A built/bundled course editor must be rebuilt
  for the editor source changes to take effect.
