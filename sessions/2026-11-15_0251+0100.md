# Why inverted leg 3 follows a different route

The source leg used for inverted stage 3 is structurally unique. Its racer
start is on intersection tile `0x7A`; the other four source legs start on
straight tiles `0x31` or `0x33`. Leg 3 is also the only one whose two opponent
branch scripts match (`2 → 2 → 3 → 2`).

The current inversion code explicitly treats that intersection case:

- It moves the finish beyond the intersection onto the ground-road exit.
- It constructs the new start with tile `0x30` and resets both opponent lane
  indices from `0x43` to `0x40`, because tile `0x30` has only three waypoint
  records. The lane proceeds through waypoints 0, 1, and 2, then links to tile
  `0x58`.
- The other stages keep their straight start tile, `0x43` waypoint index, and
  original scripts. This means their rotated lane networks can produce a
  different route.

The special topology and matching scripts are the strongest explanation for
leg 3's distinct route, but they have not been isolated experimentally.

## Test-file caveat

The available playtested `TD3_SCENE03/SCENE03.DAT` is not identical to a fresh
output of the current inversion code: 27 bytes differ, including five in leg
3. In the playtested file, the new start is tile `0x78` at `(2,14)` with
waypoint `0x43`, and the finish is tile `0x59` at `(30,2)`. The current
inversion instead uses tile `0x30` and waypoint `0x40` at the start, and puts
the finish at `(0,2)`. Both opponents' traces reach the finish in the
playtested file; both end with `script-ended` before the detected finish in a
fresh current output. The user's in-game confirmation therefore applies to
the earlier layout; the current export still needs a separate playtest.
