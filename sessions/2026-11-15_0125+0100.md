# Recovering archived Cape Cod lane data

## What changed

- Confirmed `SCENE02.LST`'s archive directory points to `SCENE02P.BIN` inside
  `SCENE02.DAT` at offset `0x1D11A`. The game's archive loader resolves this
  entry before trying to open a loose file, so a separate `SCENE02P.BIN` is not
  required.
- Updated the course editor to extract that bank from the DAT. The private
  bank has 127 index entries; its first waypoint record begins immediately
  after those entries. Added a test against the bundled SCENE02 files.
- Route traces now start from each opponent entity's stored cell index, rather
  than deriving a cell from rounded world coordinates.
- Updated the READMEs in the enhanced game, enhanced-analysis, and course
  editor forks to describe their analysis-driven changes and link to these
  session records.

## Current route findings

With the archived Cape bank and stored start cells, the first three Cape Cod
traces still end when their opponent scripts end, before reaching the detected
finish. Leg 1 ends at tiles `0x68` and `0x44`; legs 2 and 3 end at tile `0x15`
for both opponents. The editor now uses the right data source, but this does
not yet explain why the expected in-game routes are believed to reach the
finish.

Re-tracing the user's playtested inverted Pacific DAT with stored start cells
still predicts the same-cell U-turn fallback on inverted leg 1 only. Script
end occurs before finish for one opponent on leg 1, one on leg 2, both on leg
3, one on leg 4, and both on leg 5. This remains different from the reported
in-game U-turns on all legs, and the tracer does not simulate steering or
vehicle timing.
