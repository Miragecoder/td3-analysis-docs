# SCENE music (.MUS) investigation

## Context

User asked how music works in SCENE files: each scene comes with 3 music files toggled as "radio channels", and whether they are OPL instructions / MIDI-convertible.

## Findings

### Naming and selection

- Race music is handled by `music_for_state` case 5 in `td3-analysis-docs/repos/testdrive3-enhanced-analysis/src/sound/api.c`.
- It builds `SCENEnnA/B/C.MUS` from the active scene path: appends `.MUS` and sets the station letter to `'A' + track` (`/* A/B/C = radio station */`), loads into `DS_scene_music_buf`, plays via `music_play`.
- Radio toggle is `key_radio` in `td3-analysis-docs/repos/testdrive3-enhanced-analysis/src/game/sim_controls.c`: increments `DS_radio_station`, wraps at 3, calls `music_for_state`.
- Race/leg reset restarts current station (`src/game/flow_race.c:198`).

### Format

- Not MIDI and not a raw OPL register dump. It is a custom TD3 sound-driver event stream.
- `music_play` (`src/sound/driver.c`) skips initial `u16`, sets music cursor/control/wait/master volume, claims voices.
- `snd_tick` parses events: reads 4 bytes, status low nibble maps through `instr_chmap`, bits 6..4 = event type, bit 7 = delta follows; advances by `DS_event_len[type]`; dispatches `DS_music_handlers[type]`; reads 1-byte or extended 14-bit delta.
- Event handlers: note off, note on, loop, stop point, program, loop exit, hook, end (`mus_ev_*` in `src/sound/driver.c`).
- Device backends render events: AdLib/OPL2 writes OPL registers (`src/sound/adlib.c`, Nuked-OPL3 in port), PC speaker uses PIT (`src/sound/speaker.c`).

### Instrument bank

- Instruments come from `INSTR.DAT`, not embedded in `.MUS`. `instr_load` loads section 0: device name, 0x162-byte table block (`progmap`, `veloff`, `chmap`, `percmap`, count, size), then instrument data.
- `Game/INSTR.DAT` section 0 parsed as: `Ad-lib Sound Board`, 82 instruments, 9 bytes each (OPL2 FM patch records), 128-entry progmap, 128-entry veloff, 16-entry chmap.
- No human-readable instrument names in bank; raw OPL params visible.

### PC speaker

- No separate PC speaker file. Same `.MUS` stream, different active device backend selected by `music_init`/`snd_select_routines`.
- `spk_note_on` accepts voices <= 2, forces all to voice 0 (monophonic), converts note (`MIDI - 24`), sets PIT channel 2 frequency and speaker gate. Notes >2 ignored by backend; allocation/priority decides winners on voice 0.

### MIDI conversion

- No existing converter in repo. Conversion is feasible in principle with a custom tool, but not lossless/straightforward.
- Export to MIDI: note/program/deltas map conceptually; need to handle TD3 loops/hook/stop/end, instr_chmap, instrument bank/OPL patches, device semantics.
- Import from MIDI: only constrained subset; must generate valid TD3 events and map to existing instrument bank/driver behavior.
- A native TD3 .MUS sequencer/editor, with optional MIDI import/export, is the most faithful approach.
