# SCENE UI bitmap editing (LZW/RLE codec, editor replace & fit)

Investigated and implemented drop-in editing for UI bitmaps stored in
`SCENE01.DAT`/`SCENE02.DAT` (route title/icon and landscape pairs), plus
SCENE03 experiment landscape-swap groundwork.

## Findings

- Scene UI bitmaps are **compressed, not raw bitmaps**: `LZW (9–12 bit,
  LSB-first, clear 256/end 257) -> RLE -> indexed pixels`, with widths
  hardcoded/known per slot and palette banks applied per image
  (`spec/image-format.md`, `imgextract` manifest/layout).
- Title/icon/landscape blocks live at **fixed offsets/sizes** in the scene
  DAT layout (not relocatable via the LST archive directory), so in-place
  replacement is only straightforward when recompressed data fits the
  original slot. SCENE01 landscapes form 3 sets (palette + ground 320×50 +
  sky 320×19): A leg 1/coast, B legs 2–4/farmland, C leg 5/Yosemite.

## Codec and patching (`repos/testdrive3-course-editor`)

- Added TD3-compatible `lzwEncode` in `src/shared/lzw.ts` (mirroring the
  decoder’s bit packing, dictionary growth/reset and width-expansion
  timing) and emit an initial **CLEAR** code for game-decoder
  compatibility (fixes structurally garbled/overrunning output seen
  in-game).
- Fixed `rlePack` in `src/shared/rle.ts` to split runs >255 into valid
  8-bit length-byte chunks (previous truncation corrupted repacks).
- Added `encodeTd3Image`, `removePixelBase`, and `replaceTd3ImageSlot`
  (reject-if-bigger, zero-pads remainder) in `src/shared/td3-image.ts`.
  Verified round-trips on SCENE01 slots; recompressed size can differ from
  the original (e.g. `landA` re-encodes larger than its slot).

## Scene image slots and editor UI

- Added `src/shared/scene-dat-images.ts` with SCENE01/SCENE02 UI bitmap
  slot definitions (offset/size/dimensions/palette refs), decode/encode/
  replace helpers, and `swapScene01LandscapeSetsAandC` (swap palettes and
  re-encode A↔C landscape images into destination slots, validating fit).
- Added a **“Scene UI bitmaps”** panel to the course editor
  (`editor.html`, `src/browser/editor.ts`): select a slot, preview
  (correct palette: default VGA for title/icon, scene 112-color bank at
  16–127 for landscapes), export PNG, **Replace from image…** (exact
  `WxH`, nearest-color remap, RLE+LZW, drop-in only if it fits), and
  **Fit & replace…** (lossy, best-effort: progressively consolidate
  palette indices/remap to fewer colors until encoded size fits).
- Fixed import **vertical flip** (canvas top → TD3 top/buffer bottom-up)
  and constrained landscape mapping/fitting to palette-bank indices 16–127.
- **Create SCENE03 experiment**: optional (default-on) attempt to swap leg
  1↔5 landscapes/palettes (set A↔C); warns and continues if the swap
  cannot fit destination slot sizes.

## Status / known issues

- Route/title replacement works in-game with the codec fixes; normal
  replace is structurally correct when it fits.
- `Fit & replace…` fits tight slots (e.g. title) but **some fitted
  landscape replacements still showed corruption in-game** during testing;
  landscape palette-bank/index handling was tightened, but this needs
  further investigation (control: unedited export → Fit & replace on a
  landscape). Some slots (notably `landA`) do not round-trip-fit with this
  encoder, so fitting is inherently lossy and slot-size-limited.

## Validation

- `npx --no-install tsc -p tsconfig.json --noEmit` passes in
  `repos/testdrive3-course-editor`.
- Codec round-trips verified on SCENE01 image slots (decode/repack/encode/
  decode equality); in-game confirmation that a replaced route icon renders
  correctly after adding the initial CLEAR and fixing import orientation.
