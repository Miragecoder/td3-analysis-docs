# Course editor: lane connectivity and AI route decision markers

Continued map-editor work in `repos/testdrive3-course-editor`, focusing on making
tile waypoint/route behavior easier to understand.

## Lane connectivity (entry → available exits)

- Added `getTileConnectivity(lane)` in `src/shared/lane-connectivity.ts` to
  compute, per entry waypoint, which exit waypoints/sides are reachable within a
  tile by traversing the lane graph. Traversal considers standard branch
  behaviors (2/3/4), including control-point behavior changes, so
  behavior-dependent alternatives are included in the reachable-exit set.
- Updated `src/browser/editor.ts` so the **Selected cell** inspector shows, for
  the placed/rotated cell, **entry → available exits by world side**
  (N/E/S/W). This surfaces flow per approach (e.g. straights, curves,
  intersections with multiple exits, and overpass-like independent flows such as
  N→S and E→W), plus notes for tiles with no lane record/waypoints/entries or
  exit-only sides.
- Added a compact route summary to the waypoint hover overlay tooltip and styled
  `#cell-details` with preserved line breaks (`src/browser/editor.css`).
- Fixed a runtime bug in the new connectivity code: `Set` results were mapped
  directly (`reachable.map is not a function`); converted reachable indices to an
  array before mapping/sorting.

## AI route script decision markers

- Extended `LaneRouteStep`/`traceOpponentLaneRoute` in
  `src/shared/lane-routes.ts` to annotate control-point steps with the consumed
  script branch index/value (`scriptStepIndex` / `scriptStepMode`).
- In `src/browser/editor.ts`, when **Show AI route 1/2** is enabled, render
  on-map decision markers for each visible traced route: the **initial mode** at
  the start cell and each **consumed branch step** value at the control-point
  cell where it applies (opponent-colored, with tooltip details). Marker
  rendering is decoupled from polyline drawing so decisions still show for short
  traces.
- Added decision-marker overlay styles in `src/browser/editor.css`.

## Findings / clarification (SCENE03, LEG1)

- Inspected tile `0x24` at cell (6,13), rot 270°, elev 6 (SCENE03 LEG1,
  `Game/SCENE03.DAT`, map offset `0x10240`): world-side connectivity resolves to
  **N → W, E → W, W → E, W** (no `W → N`). Opponents start at (4,13) with
  scripts `[init 2, 2,2,2, term]` and `[init 3, 3,2, term]`.
- Conclusion: from a west approach this tile’s lane graph offers exits on E and W
  only (including a same-side path), so branch scripts can select among existing
  branches but cannot create a north exit; the tile/waypoint connectivity appears
  mismatched for a west→north/east intersection expectation. A follow-up check
  suggested traffic follows the same lane topology (with different branch-choice
  logic than scripted opponents) and did not take a west→north exit here either.
- Clarified that branch script numbers are behavior modes consumed in order at
  lane control points (initial mode + branch steps; 0 terminates), selecting
  encoded branch alternatives for the current waypoint rather than naming turns
  directly.
