# 2026-11-15 — Extending route traces to both courses

## What changed

- Removed the Pacific-only route-view restriction. The editor now identifies
  each leg's finish by scanning tile face material `0x1F`, finding Pacific
  finish tile `0x59` and Cape Cod finish tile `0x51`.
- The editor reads the scene LST lane-bank selector. It loads a private
  `<scene>P.BIN` when the LST requests one and the file exists; otherwise it
  shows a dashed shared-bank candidate. Scene-specific banks are parsed with
  all 128 possible tile-index entries.
- Centralized tile-bank offsets/counts and added tests for both finish tiles
  and scene bank selection.
- Updated docs with the important distinction: the provided Pacific
  `SCENE01.LST` and experimental `SCENE03.LST` use shared `SCENETTP.BIN`;
  Cape Cod's `SCENE02.LST` requests `SCENE02P.BIN`.

## Available assets and remaining mismatch

No P.BIN files are present in the supplied game-data directories. Cape Cod
traces therefore use the shared bank and cannot be treated as its actual
in-game routes. The private file needed for an exact Cape trace is
`SCENE02P.BIN`.

The inverted Pacific course does not need a private P.BIN according to the
provided `SCENE03.LST`; it uses the shared bank. The shared-bank trace predicts
a U-turn on inverted leg 1 only, which does not match the user's report of
immediate U-turns on all legs. The `TD3_SCENE03` copy in this workspace is
documented as a day/night-only variant, not the inverted DAT used in that
playtest. The exact tested `SCENE03.DAT` and active `SCENE03.LST` are needed to
compare the trace to the run.

## Validation

- Seventeen editor tests passed.
- `npm run build` passed; only the existing Node-module externalization

- Confirmed LST selector bytes: SCENE01 `1` (shared), SCENE02 `0` (private),
  SCENE03 `1` (shared); no P.BIN is present in the supplied folders.
