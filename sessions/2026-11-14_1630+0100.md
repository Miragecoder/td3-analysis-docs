# Initial codebase walkthrough

**When:** 2026-11-14 16:30 (+01:00)

**Repositories examined:** `testdrive3-enhanced`, `Test-Drive-3-Maps`

## Findings

- The C repository is an SDL3-native C11 port of *Test Drive III: The Passion*
  (1990), not a DOS emulator. It loads the user's `TDIII.EXE` or `TD3.EXE` and
  game data files; original game files are not included.
- `src/mem.h` models real-mode segmented addresses in `mem[]`; this is the
  direct-memory idiom behind expressions such as `DSW(DS_game_state)`.
  The port places VGA mode 13h page 0 at `A000:0000` in that same memory array.
- `src/mem.c` unpacks EXEPACK when needed, applies MZ relocations, checks the
  expected executable image, and provides the runtime divide-error handler.
- `main()` initializes the loader, host, VGA, and modules. `game_main()` in
  `src/game/flow.c` is the game-state loop; `race_run()` in
  `src/game/flow_race.c` coordinates simulation, rendering, and race pacing.
- The faithful core is divided among `game/`, `platform/`, and `sound/`.
  `host.*` adapts SDL3 for original-style timer, input, screen, and audio
  services. `src/enhanced/` is a separate renderer that snapshots game frames
  and composes a smooth, higher-resolution view over VGA output.
- `Test-Drive-3-Maps` is a separate TypeScript/Vite map and asset extractor and
  viewer. Its README and `spec/` describe TD3 data formats; it is not the C
  runtime, though the repositories concern the same game.
- `ENGINE.md` refers to upstream `td3port/` reverse-engineering specs and
  disassembly tools not included among the checked-out workspace repositories.
