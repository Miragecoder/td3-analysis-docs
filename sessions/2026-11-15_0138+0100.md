# Confirming inverted Pacific route turns

The user reviewed the editor's route rendering and confirmed that the
opponents' paths turn back before apparent dead ends on inverted Pacific legs
1, 2, 4, and 5, then continue in the intended direction. Leg 3 is different:
its rendered route does not turn back, and the user reached leg 3 in-game and
confirmed that the opponents immediately head in the correct direction.

This resolves the apparent conflict with the tracer's U-turn count. That count
only records the engine's same-cell dead-end fallback when an exit has no
matching entry in the neighboring cell; it does not count every reversal in a
connected waypoint sequence. Do not treat a zero fallback count as proof that
a rendered route never turns around.

The tracer still reports script termination before the detected finish for
some inverted Pacific opponent paths. This has not been correlated with
in-game opponent visibility or completion and remains separate from the
confirmed turn behavior.
