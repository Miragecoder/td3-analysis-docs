# SCENE03 land image replacement, export, and LZW crash debugging

## Context

Follow-up to the earlier variable-size title/icon work in `td3-analysis-docs/repos/testdrive3-course-editor`. Goal: extend scene image replacement to `landA-F`, then debug SCENE03 export/game crashes and visual corruption reported with `Game/SCENE03.DAT`/`SCENE03.LST`.

## Changes (course editor)

- Generalized scene image overrides to `sceneImageOverrides` for all scene image slots, including `landA-F`.
- Export recomposes DAT+LST for variable-size image slots: writes `encoded + 1` padding byte, sets LST stored size to `encoded.length + 1` (TD3 `file_load_far` reads `size - 1`), shifts subsequent LST offsets by cumulative delta.
- Updated `scene_pic_pairs` npairs on export for replaced land slots. Correct mapping:
  - `landA/B` = leg 0 = pic_pairs `2/3`
  - `landC/D` = leg 1 = pic_pairs `5/6`
  - `landE/F` = leg 4 = pic_pairs `14/15`
- Removed automatic shared land-palette regeneration on replace/generate. It rebuilt the shared 112-color palette and remapped the paired slot, corrupting the untouched pair member. Replaced land images now quantize to the existing shared palette (palette may be slightly off).
- Restored delayed/pending LZW encoder width expansion in `src/shared/lzw.ts`. Immediate expansion produced streams that desynced with TD3 decoder behavior and caused “Could not decode this image slot” / corrupted renders.
- Optimized LST hot paths: skip expensive name resolution where not needed; replaced SCENE03 LST generation brute-force resolver with candidate hash lookup.

## Bugs found/fixed

| Symptom | Cause | Fix |
|---|---|---|
| Browser hang on export | Expensive recomposition/name resolution on hot path | Optimized LST resolution, added export progress/yield |
| Game crash after land replacement | LST stored size written as `encoded.length`; game read `size-1`, missing last byte; end code unreadable, LZW runaway corrupted DS | Write DAT gap/LST size as `encoded.length + 1` |
| “Could not decode this image slot” / corrupted images | LZW encoder used immediate width expansion; TD3 expects delayed expansion | Reverted encoder to delayed/pending expansion |
| Paired land corrupted when replacing other pair member | Auto palette regeneration remapped paired slot to new palette | Removed auto palette regen; quantize to existing palette |
| Land placement/corruption after replacement | Stale `scene_pic_pairs` npairs in LST header | Recompute npairs from decoded RLE and write mapped pic_pairs entry |
| landE/F corrupted while A/B/C/D worked | landE/F mapped to pic_pairs 8/9 (leg 2) instead of 14/15 (leg 4) | Fixed mapping to 14/15 |

## TD3 enhanced

Temporary debug logging was added in `testdrive3-enhanced-analysis` to diagnose the LZW runaway (lzw out/refill/trace, pic_draw, scene_select path). User confirmed fixes; logging changes reverted.
