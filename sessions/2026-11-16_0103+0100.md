# AI route inspection, editing, and path probing

Extended the course/map editor so opponent AI data can be inspected and
edited, and so valid no-U-turn paths can be generated from the lane/waypoint
network.

## Editor UI and visualization

- Added manual editing of AI opponent branch scripts (`initialMode` and
  branch steps) in the opponent route panel. Script edits are written to the
  in-memory working copy and applied to route visualization/tracing
  immediately; changes persist via normal DAT export.
- Added editing of map entity records (flags, x/z/y, heading, velocity, cell,
  waypoint index) with immediate visualization/status refresh.
- Added tile-grid zoom and a scrollable grid container/layout fixes so the
  map remains usable when zoomed.
- Split route visibility into separate **Show AI route 1** / **Show AI route
  2** toggles (opponent 1 = model 0x02, opponent 2 = model 0x03) so each
  traced path can be inspected independently.
- Added a waypoint overlay toggle showing lane waypoint indices/types/sides
  (entry/exit/internal) with hover-focused per-cell rendering and de-overlapped
  markers. Internal positions are schematic (tooltips expose flags/coords).

## Path probing and generation

- Added `src/shared/route-probe.ts` to probe valid no-U-turn routes for an
  opponent from the lane bank, mirroring `traceOpponentLaneRoute` control-flow
  semantics (branch offset chosen from current behavior at a waypoint; a
  consumed script step becomes the behavior for subsequent waypoints), with
  deterministic mode candidates `{2,3,4}` at control points.
- Added **Generate AI paths** UI in `src/browser/editor.ts` that probes both
  opponents, prefers two shortest distinct paths that diverge and reconverge
  (shared start/finish allowed), reports exit/entry-link and scripted
  control-point counts, and can apply a suggested script to one or both
  opponents. Single-path/no-distinct-alternative cases are reported.
- Added copy-paste-friendly console logging of probe/generation details
  (`[path-probe] context`, per-opponent candidates, `COPY_SUMMARY`,
  `COPY_SELECTION`).

## Probe fixes and spur filtering

- Fixed probe search termination: it now continues until enough **unique**
  route signatures are found (instead of stopping on raw finish hits), which
  allows longer/divergent alternatives to be discovered (e.g. SCENE01 leg 5
  original-style `initial 3, [3,2]` / 286-step branch via `3,4,22 -> 3,4,18`).
- Disqualified same-tile out-and-back spurs during probing: if a lane-link
  would re-enter a previously visited map tile after leaving it (e.g. a
  broken-bridge/overpass detour that diverges and reconverges on the same
  tile), the path is rejected as a dead-end branch. Rejections are reported as
  `rejected.sameTileSpur`. This removes spur routes in cases such as SCENE01
  leg 5 (`19,1 -> 18,1 -> 19,1`) and also improves path finding on some Cape
  Cod courses.

## Validation

`tsc --noEmit` passes for the editor source. `dist/` was not rebuilt in the
session environment (Vite requires Node 20.19+); rebuilt bundles are needed
to run the updated probe/editor behavior.
