## Course object and gameplay investigation

- Traced special ground surface codes: `0x1C` wind, `0x1D` rain, `0x1E` snow,
  and `0x1F` finish. These come from polygon surface/material data in the
  selected tile geometry, rather than a separate weather-cell list.
- Confirmed that tile IDs select lane entries in `P.BIN`; their waypoint
  records are transformed by map-cell rotation. The lane bank is course
  specific when configured and otherwise uses `SCENETTP.BIN`.
- Sampled all five SCENE01 map starts. Each has an object in slot 0 with flags
  `0x2001`, model `0x01`, and per-leg coordinates; `car_leg_reset()` reads
  object 0's heading. The exact coordinate-copy step into runtime sprite
  state remains untraced.
- Confirmed shuttle behavior for entity behavior values below 2 and 9, and
  identified police models `0x11` and `0x30`. The enhanced port intentionally
  starts police pursuit after the player passes, unlike the original behavior
  described in the source.
- Found a collision handler for model `0x39` that stops velocity and waypoint
  state; its comment says “seagull takes off.” Whether this is the
  chicken-like object from the playtest and how its visual flip occurs remain
  uncertain.
- Added `docs/map-entities-and-gameplay.md` and linked it from the course
  structure and analysis index.
