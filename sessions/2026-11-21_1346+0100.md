# Route capture in TD3 and route-marker editing in the course editor

## Context / question
User asked how Test Drive III captures which route a player took on a 5-leg scene (typically 2 Highway routes + Shortcut per leg), given that the scorecard shows the route name. Follow-up: make those route-marker tiles visible in the course editor and allow manipulating them. Then clarified route-name labeling and whether route markers are tilemap positions vs tile-type IDs.

## Findings

### Route names / records
- Scene `.LST` stores 36 fixed 12-byte route-name slots at `0x0058`: 5 legs × 4 names (main/leg name + 3 alternatives), plus placeholders (`spec/lst-file-format.md`, `src/shared/scene-lst.ts`).
- `leg_results()` in `testdrive3-enhanced-analysis/src/game/flow_scores.c` uses `DS_route_index` to display the route name and to merge/show per-route best records in `DS_hi_route_best + (li * 3 + ri) * 8` (3 route slots per leg).

### Runtime route capture
- `DS_route_index` is `u8` at `DS:0x0A74` (`symbols.h`), reset to 0 in render setup.
- `DS_route_tiles` is `u8[3]` at `DS:0x95C9` (`symbols.h`), corresponding to per-leg map header offsets `0x37..0x39` (IDA `byte_285B5/285B6/285B7`; map base `DS:0x9592`, `DS_colour_mode` is `map+0x35`).
- `world_build_visible()` (`render_world.c`) reads the current cell’s tile type and compares it against the 3 route tile IDs; on match it sets `DS_route_index` to 0/1/2. This is a **tileset/tile-type ID** check, not a tilemap cell-position reference. Any cell using a route-marker tile type can trigger that route; marker tile types should be unique to the intended route.

## Course editor implementation (`td3-analysis-docs/repos/testdrive3-course-editor`)

- **`src/shared/course-map.ts`**: added `ROUTE_TILES_OFFSET = 0x37`, `ROUTE_TILE_COUNT = 3`, `readRouteTiles()`, and `writeRouteTile()` for per-leg map header route-marker tile IDs.
- **`editor.html`**: added a “Route markers” panel with 3 editable tile-ID inputs and legend entries.
- **`src/browser/editor.css`**: added route-marker cell border/badge styling and legend key styling (`R0/R1/R2`).
- **`src/browser/editor.ts`**: wired route-marker UI refresh, highlighted grid cells whose `tileId` matches a route-marker tile type, showed marker info in cell details/titles, and wrote input changes back to map header bytes. Route labels use the 3 alternative LST slots per leg (`leg * 4 + index + 1`), not the main/leg slot.

## Corrections during session
- Initial label mapping used `leg * 4 + index`, which incorrectly showed the leg/main slot (e.g. “Scenic Coast”) as Route 0; corrected to use the 3 alternative slots.
- Initial offset used `0x2B..0x2D` (wrong; yielded `0,192,17` for SCENE01 leg 1); corrected to `0x37..0x39`, yielding `112 (0x70), 34 (0x22), 81 (0x51)`.
